# 常见问题解答 (FAQ)

## 一、 服务器基本信息

**Q1：服务器使用什么核心和版本？**

A：服务器核心为 **Purpur 1.21.11**（Minecraft 1.21.11）。Purpur 是 Paper 系的高性能服务端核心，在保证稳定与性能的同时提供丰富的配置能力。

**Q2：服务器是什么类型的？**

A：星穹旅驿是一个以**阵营对抗**为核心的乱世生存服务器：大崩裂之后，**黎明誓约**与**暮夜同盟**两大阵营争夺星穹界的未来，同时保留原版生存的核心乐趣。详见[阵营玩法总览](/for-new/factions/)。

**Q3：服务器有哪些核心功能？**

A：

- 阵营对抗玩法（内测中）：黎明誓约 vs 暮夜同盟（基于 ImprovedFactions 搭建），详见[阵营玩法总览](/for-new/factions/)
- 服务器菜单系统：游戏内图形菜单，常用功能一键直达
- 基岩版互通：手机玩家与 PC 玩家同服游玩

## 二、 客户端与连接

**Q4：我应该使用哪个版本的客户端连接服务器？**

A：服务器通过 ViaVersion / ViaBackwards 支持多版本 Java 版客户端。为获得最佳体验，**推荐使用 1.21.11 客户端**。

**Q5：手机能玩吗？**

A：可以。服务器通过 Geyser + Floodgate 支持基岩版玩家与 Java 版玩家同服游玩，服务器地址与端口和 Java 版相同（`serverone.codeyun.com:12000`），见[基岩版进服教程](/for-new/join-server/for-bedrock-client/)。

**Q6：需要下载专用的客户端整合包吗？**

A：不需要。所有功能均集成在服务端，使用对应版本的官方或纯净客户端即可正常游戏。你可以选择性安装光影、材质包、性能优化等客户端美化组件。

**Q7：允许使用模组（Mod）吗？**

A：允许使用不影响游戏公平性的客户端辅助模组，例如：

- 允许：小地图（JourneyMap、Xaero's）、光影（Optifine、Iris）、性能优化（钠）等
- 严格禁止：任何提供自动化优势、飞行、加速、透视、自动攻击等功能的作弊模组/客户端。如有疑问，请务必事先咨询管理员

## 三、 账号与登录

**Q8：第一次进入服务器需要做什么？**

A：新玩家首次进入需要注册账号，以保护您的角色数据：

- 注册账号：输入 `/register 你的密码 重复你的密码`
- 登录账号：之后每次上线或掉线重连后，输入 `/login 你的密码`

**Q9：忘记密码怎么办？**

A：及时联系在线管理员，提供您的游戏 ID，管理员可以协助重置密码。

## 四、 阵营玩法

**Q10：什么是阵营玩法？**

A：服务器原创的阵营对抗玩法：大崩裂后的星穹界分裂为「黎明誓约」（秩序、守护）与「暮夜同盟」（自由、强者为尊）两大阵营。双方在昼夜增益、核心资源、主城风格、积分来源、世界事件上完全镜像对立，设计目标是长期拉锯，而不是一次性决战。详见[阵营玩法总览](/for-new/factions/)与[阵营对抗机制](/for-new/factions/mechanics)。

**Q11：怎么加入阵营？**

A：**内测资格申请已在服务器官网开放**：注册并登录官网账号后，进入「阵营内测」页面填写申请（MC ID、期望阵营、周游戏时长、加入理由等），等待审核结果。后续登录服选阵营界面上线后，进服即可直接选择阵营。

**Q12：现在不选阵营可以吗？**

A：可以。申请表单提供「暂不选择」选项，你可以先体验生存玩法，之后再做决定也不迟。

**Q13：两个阵营有什么区别？**

A：一句话概括——黎明誓约要重建秩序、点燃曙光灯塔、驱散长夜；暮夜同盟要维持永夜、夺取星穹核心、让强者制定规则。白天黎明方享有防御/恢复增益（"黎明庇护"），夜晚暮夜方享有速度/夜视/攻击增益（"长夜同行"）；双方的主城风格、核心资源与积分来源也完全不同。详细对照见[阵营对抗机制](/for-new/factions/mechanics)。

## 五、 反馈与技术问题

**Q14：为什么我进服后卡顿或频繁掉线？**

A：请按顺序排查：

1. 确认客户端版本：推荐使用 1.21.11
2. 检查网络：尝试切换网络环境（如从 WiFi 换为有线）
3. 调整客户端设置：过高的渲染距离、复杂的光影或材质包会极大影响性能，请在视频设置中适当调低

**Q15：我遇到了 BUG 或有功能建议，去哪里反馈？**

A：我们非常重视您的反馈！请加入我们的官方 QQ 交流群：**942235691**，详细描述问题或建议，管理团队会及时查看与回复。基岩版玩家遇到互通问题也可以在群内反馈（已知问题与修复进度见[服务器建设 · Issues](/develop/issues/)）。
