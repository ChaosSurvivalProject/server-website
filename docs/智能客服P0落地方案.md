# 星穹旅驿 · 智能客服 P0 落地方案（实现规格）

> 目标：官网接入一个**真的能用**的智能客服——能流式回答、能引用来源、能显示思考过程、答不了会引导进 QQ 群。
> 原则：只做 P0，不面面俱到。所有实现对齐仓库既有规约（领域模块单文件、响应包络、String(30) 北京时间、camelCase alias）。
> 生产形态：**直接部署（非 Docker）**，Nginx 同域单入口。
>
> **本文只写「要做什么、怎么做、怎么验收」。** 选型依据、被否决的方案、实测数据、风险取舍一律见 **[智能客服技术决策记录](智能客服技术决策记录.md)**，本文不复述理由。

## 1. 范围

### 1.1 做什么

1. **知识库表 + 摄入链路**：wiki 文档 → 解析 → 切片 → Embedding → 落库
2. **同步脚本** `kb_sync.py`：按文件 MD5 增量同步 wiki（本地/服务器执行，线上只读）
3. **对话接口** `POST /kb/chat`：SSE 流式，向量 + 关键词混合检索，动态提示词注入实时状态
4. **主站悬浮客服组件**：流式打字机、思考过程折叠、来源引用、QQ 群引导
5. **后台知识库页**：列表 / 粘贴新增 / 删除 / 切片预览 / 重建索引
6. **SERVERS 持久化**：服务器地址存入 DB，重启不丢
7. **限流与总开关**：防账单事故

### 1.2 明确不做（P0 一律不做）

- ❌ 人工客服 / 工单 / 截图上传 / 通知渠道
- ❌ 文件上传（PDF / DOCX / HTML 解析）——入库只走"脚本读 wiki"和"后台粘贴文本"
- ❌ 本地 Embedding 模型
- ❌ LangChain / LangGraph / Agent / Tool 调用
- ❌ sqlite-vec / numpy / Faiss / 向量数据库
- ❌ Redis / 会话表 / 对话历史落库（多轮由**客户端**携带 `history` 数组，服务端无状态）
- ❌ 真实玩家在线人数（`mcstatus`）——P0 只用现有 TCP 探测给"在线/离线"，人数进 P1
- ❌ 语音、虚拟形象、游戏内聊天接入、知识库自动定时任务（用 crontab 就够）
- ❌ 后台文档上传、富文本编辑、标签体系、检索效果看板

### 1.3 可裁剪项（想再压工期时按序砍）

| 序 | 砍掉 | 省 |
|---|---|---|
| ① | FTS5 混合检索（只留向量） | 0.5 d |
| ② | 后台知识库页 | 0.5 d |
| ③ | SERVERS 持久化（代价：状态注入重启后失效） | 0.5 d |

### 3.2 FTS5 与配置键（原生 SQL，在 `init_db()` 中建，不进 `Base.metadata`）

```sql
-- 全文索引：trigram 分词器（unicode61 不切分中文，必须换）
CREATE VIRTUAL TABLE IF NOT EXISTS kb_chunks_fts
USING fts5(content, tokenize='trigram');
```

`kb_settings` 的键约定：

| key | 含义 |
|---|---|
| `index_version` | 每次摄入/删除后自增，服务端凭它判断内存索引是否失效 |
| `embed_model` | 写入时的 embedding 模型名 |
| `embed_dim` | 向量维度 |
| `kb_schema_version` | 建表版本，便于后续迁移 |

**启动时拿 `embed_dim` 与 `KB_EMBED_DIM` 比对，不一致直接拒绝启动向量检索**（打 ERROR，自动降级为仅 FTS），避免脏检索引擎静默返回垃圾结果。

### 3.3 WAL 与忙等待（**必做，否则同步脚本写库必冲突**）

服务进程用 `StaticPool` 长期持有唯一连接；`kb_sync.py` 是**另一个进程**要写同一个文件 → 不开 WAL 就是 `database is locked`。

在 `init_db()` 里加：

```python
async with engine.begin() as conn:
    await conn.run_sync(Base.metadata.create_all)
    # journal_mode 持久化在库文件里；busy_timeout 是连接级，每次启动都要设
    (await conn.exec_driver_sql("PRAGMA journal_mode=WAL")).scalar()
    await conn.exec_driver_sql("PRAGMA busy_timeout=8000")
    await conn.exec_driver_sql("PRAGMA synchronous=NORMAL")
```

`kb_sync.py` 用同步 `sqlite3` 连接，同样设 `journal_mode=WAL` 与 `busy_timeout=8000`。

> 开了 WAL 会在 `backend/data/` 下生成 `-wal` / `-shm` 文件。该目录已 gitignore，无需额外处理。

## 4. 接口契约

### 4.1 公开接口（主站用）

| 方法 | 路径 | 用途 | 响应 |
|---|---|---|---|
| `GET` | `/kb/info` | 客服元信息（开关、标题、欢迎语、示例问题） | `{code,message,data:{enabled,title,greeting,faq:[...],model}}` |
| `POST` | `/kb/chat` | **SSE 流式问答**（仅登录用户，`Authorization: Bearer <JWT>`） | `text/event-stream`（见 §4.3，**不走包络**） |

`POST /kb/chat` 请求体：

```json
{
  "message": "服务器IP是多少",
  "history": [
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ]
}
```

- `history` 可选，服务端**只取最后 `KB_MAX_HISTORY`（默认 6）条**，忽略超长内容；不落库、不建会话。
- `message` 去空白后长度上限 `KB_MAX_INPUT_CHARS`（默认 300），超出 400。
- **需登录**：请求头须带 `Authorization: Bearer <JWT>`（`streamChat` 自行注入，与 axiosInstance 请求拦截器同口径）；未登录/过期返回 401（流前错误，标准 HTTP + `detail`），前端 ChatWidget 以登录引导替换输入区，不整页跳转。

### 4.2 管理接口（`require_admin`）

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/kb/admin/documents` | 分页列表（`page` `pageSize` `sourceType` 筛选） |
| `POST` | `/kb/admin/documents` | 手动新增（`{title, content}`）→ **同步**切片 + Embedding |
| `DELETE` | `/kb/admin/documents/{id}` | 删除（`source_type='wiki'` 拒绝，返回 400 提示走脚本） |
| `GET` | `/kb/admin/documents/{id}/chunks` | 切片预览 |
| `POST` | `/kb/admin/documents/{id}/reindex` | 重建切片与向量（幂等：先删后建） |
| `GET` | `/kb/admin/stats` | 文档数 / 切片数 / 索引版本 / 维度一致性 / 总字符数 |

字段命名：对外 camelCase（`sourceType` `chunkCount` `createTime` `updateTime` `indexVersion`），Pydantic 用 `alias` + `populate_by_name=True`。

### 4.3 SSE 帧协议（定稿，全文唯一版本）

```
data: {"sources":[{"id":12,"title":"进服教程 / Java 客户端","sourceType":"wiki","score":0.83}]}
data: {"reasoning":"用户问的是服务器地址，先看知识库……"}
data: {"reasoning":"知识库里提到了 serverone.codeyun.com……"}
data: {"delta":"服务器地址是 "}
data: {"delta":"serverone.codeyun.com:12000"}
data: {"fallback":true}          ← 可选：命中引导话术时附带
data: {"error":"上游服务暂时不可用"}   ← 可选：流开始后出错
data: [DONE]
```

规则：

1. **首帧固定为 `sources`**（无命中则 `"sources":[]`）。
2. `reasoning` 与 `delta` 可交错出现（部分模型先想后答）。
3. 任一帧解析失败，前端**跳过该帧**，不中断整体流。
4. `[DONE]` 一定发（`try/finally` 保证），前端凭它收尾。
5. 空行分隔，字段为 UTF-8 JSON，`ensure_ascii=False`。
6. **错误分两类**：流开始**前**的错误走标准 HTTP 错误 + 项目包络（400/429/503）；流开始**后**的错误只能发 `{"error":...}` + `[DONE]`。
7. 15 s 内无任何 token → 发一次 `: ping\n\n` 注释行保活（防中间代理掐连接）。

### 4.4 包络规约

`/kb/chat` 是**全项目唯一**不返回 `{code, message, data}` 的接口，因为 SSE 流无法包络。**这一条例外必须写进 `AGENTS.md`**，否则后人会"修正"它。

## 5. 后端实现要点

### 5.1 `app/config.py`

不引 `python-dotenv`，写约 20 行 stdlib 解析，**不覆盖已存在的进程环境变量**：

```python
def _load_env_file(path: Path) -> None:
    if not path.is_file():
        return
    for raw in path.read_text(encoding="utf-8").splitlines():
        line = raw.strip()
        if not line or line.startswith("#") or "=" not in line:
            continue
        k, v = line.split("=", 1)
        k, v = k.strip(), v.strip().strip('"').strip("'")
        if k and k not in os.environ:      # 已存在的环境变量优先
            os.environ[k] = v
```

配置项清单见 §8。所有值走到一个模块级 `KB` 对象（dataclass 即可），**不做请求级读取**。

### 5.2 切片器（`kb_ingest.py`，约 70 行）

处理流水线：

1. **清洗**：去 YAML frontmatter（`---` 首块）、去 VitePress 容器标记行（`::: tip` / `:::`）、去 HTML 注释、压缩 3 个以上连续空行。
2. **保护代码块**：以 ``` 围栏为界切段，围栏内**绝不切分**（避免把代码劈成两半）。单块超长时整块保留、允许超 `chunk_size`。
3. **按标题切分**：`#` / `##` / `###` 为一级分隔，记录**标题路径**（如 `进服教程 > Java 客户端`）。
4. **按段落/句子切分**：优先 `\n\n`，其次 `\n`，其次 `。！？；`，最后 `，`。目标 `chunk_size=600` 字符、`chunk_overlap=80`。
5. **给每块加标题前缀**：写库时 `heading` 单独存，**进 prompt 时**拼成 `【来源：{title}｜{heading}】\n{content}`。

### 5.3 Embedding 批量调用

- `POST {KB_EMBED_BASE_URL}/embeddings`，body `{"model": ..., "input": [文本...]}`，取 `data[i].embedding`（按 `index` 排序后对齐）。
- 批大小 32，顺序请求即可：**不做并发、不用 Semaphore**。
- **写入前 L2 归一化**并 `struct` 打包为 float32 BLOB；查询向量同样归一化 → 点积即余弦。
- 维度校验：返回向量长度 ≠ `KB_EMBED_DIM` → 该文档 `status='failed'`、`error_message` 写明实际维度，**不写库**。
- 失败重试一次（超时/5xx），仍失败即 `failed` 并记录。

### 5.4 `app/kb_index.py`（内存索引）

```python
class VectorIndex:
    ids: list[int]          # 与 rows 下标对齐
    rows: list[array]       # array('f')，已归一化
    dim: int
    version: str            # 对应 kb_settings.index_version
```

- `ensure_loaded(db)`：读 `kb_settings.index_version`；与 `self.version` 相同则**零开销直接返回**（每次请求一次轻量 SELECT，代价可忽略）；不同则重建。
- 重建：`SELECT id, embedding FROM kb_chunks WHERE embedding IS NOT NULL ORDER BY id DESC LIMIT KB_MAX_CHUNKS` → `array('f')` 预切行存成 list。
- 查询（实测 5–20 ms）：

```python
def top_k(self, qv: list[float], k: int) -> list[tuple[int, float]]:
    from operator import mul
    from heapq import nlargest
    return [(self.ids[i], s) for s, i in nlargest(k, ((sum(map(mul, r, qv)), i)
                                                      for i, r in enumerate(self.rows)))]
```

- 加锁：用 `asyncio.Lock` 保护重建；查询本身无副作用，可无锁。
- **脚本改了库之后服务端无需重启**：脚本自增 `index_version`，下一次对话请求自动检测并重建索引。**这是个设计点，别改成"重启生效"。**

### 5.5 检索（`app/kb_retrieve.py`）

两路合并（`KB_HYBRID_ENABLED=1` 时全开，=0 时只走向量）：

```
用户问题
├─ 向量 Top-6         （kb_index.top_k）
└─ FTS5 trigram Top-6 （见下）
        ↓ RRF: score = Σ 1/(60 + rank)
    最终 Top-KB_TOP_K（默认 5）
```

**FTS5 查询构造**（trigram 的坑位在这里）：

```python
def build_match_query(text: str, max_terms: int = 8) -> str | None:
    # trigram 只支持 >=3 字符的子串匹配；<3 字符的片段直接丢弃
    segs = [s.strip() for s in re.split(r"[\s，。！？；：、,.!?;:()（）\[\]「」【】]+", text)]
    segs = [s for s in segs if len(s) >= 3][:max_terms]
    if not segs:
        return None
    quoted = " OR ".join('"' + s.replace('"', '""') + '"' for s in segs)
    return quoted                       # 例：'"服务器IP" OR "服务器地址"'
```

- 返回 `None` 时**跳过 FTS 这一路**，只用向量结果（不要拼出非法 MATCH 字符串让 SQLite 报错）。
- FTS 表是**独立表（非 external content）**，写入时显式指定 `rowid = kb_chunks.id`，删除时 `DELETE FROM kb_chunks_fts WHERE rowid IN (...)`。**不需要触发器**。
- 未命中任何一路（最高分 < `KB_MIN_SCORE`）→ 走 §5.6 的引导话术，**不调 LLM**。

  服务端在 `sources` 为空或最高分不足时，**发兜底文本 + `{"fallback":true}`**，前端据此渲染 QQ 群按钮（链接取 `McConfig.qqGroup.inviteLinkUrl`，走既有配置层）。

### 5.7 SSE 端点（`app/kb.py`）

```python
@router.post("/chat")
async def chat(req: ChatRequest, request: Request, db=Depends(get_db), _=Depends(rate_limit)):
    ...
    return StreamingResponse(gen(), media_type="text/event-stream", headers={
        "Cache-Control": "no-cache",
        "Connection": "keep-alive",
        "X-Accel-Buffering": "no",     # 只对 proxy_pass 直连生效，Nginx 侧仍要 proxy_buffering off

```

必须处理的七件事：

1. **流前错误**：超长/空消息/限流/未配置 API Key → 直接 `HTTPException`（标准包络 + 正确状态码），不要"先 200 再报错"。
2. **`try/finally` 关上游连接**：`async with client.stream(...) as r` + `finally` 里保证 `[DONE]`。
3. **断连感知**：生成器里每轮 `if await request.is_disconnected(): return`，避免用户关页面后还在烧 token。
4. **思考内容**：解析 `choices[0].delta` 的 `reasoning_content` 或 `reasoning` 字段（DeepSeek / 通义 thinking 模型都用 `reasoning_content`）。取到就发 `{"reasoning": ...}`，取不到就不发。
5. **厂商私有开关**：`KB_CHAT_EXTRA_BODY`（JSON 字符串）原样 merge 进请求体，用于 `{"enable_thinking": true}` 这类参数。
6. **超时**：`httpx.Timeout(connect=10, read=120, write=10, pool=10)`；read 超时按流中断处理，发 `{"error":...}`。
7. **限流**：进程内滑动窗口，单 IP 每小时 `KB_RATE_LIMIT_PER_HOUR`（默认 20）+ 全局每分钟 `KB_RATE_LIMIT_GLOBAL_PER_MIN`（默认 5）+ 单 IP 并发 1。约 35 行，无新依赖。`=0` 表示关闭。

> 取 IP 顺序：`X-Forwarded-For` 首段 → `X-Real-IP` → `request.client.host`。

### 5.8 `monitor.py`：SERVERS 持久化

改造原则：**DB 为唯一权威，内存字典为读缓存**，对外行为（含 `/monitor/servers`、`/monitor/server-info/{id}` 的响应结构）**保持不变**（首页 `OnlineCounter` 依赖它）。

1. `init_db` 后：若 `servers` 表为空，把现有硬编码的 `SERVERS[1]` 作为种子写入（保证升级后行为不变）。
2. 启动时 `load_servers()` 读 DB 填充内存 `SERVERS`（保持原 `{id: {name, address, port, is_primary}}` 结构，最小改动）。
3. 所有管理接口（增/改/删/设主）在改内存后**同步写 DB**（先 commit 再返回；失败则回滚内存改动）。
4. `_next_server_id()` 改为取 `max(DB id) + 1`。
5. 新增只读函数 `async def query_status(server_id) -> dict`，返回 `{online: bool, address, port, name}`，供客服注入。**仍用 `probe_tcp`，不引 `mcstatus`**。

⚠️ 该改造会改变"重启后地址丢失"的现存行为，属于**修 bug**，请在 `README.md` 的变更说明里写明。

### 5.9 启动流程（`main.py`）

```python
@app.on_event("startup")
async def on_startup():
    await init_db()
    await bootstrap.ensure_admin()
    await monitor.load_servers()          # 新增
    await kb.startup_check()              # 新增：见下
```

`kb.startup_check()` 做三件事，全部只记日志不阻断启动：

1. `KB_ENABLED` 为假 → 记 INFO 并跳过后续。
2. `KB_CHAT_API_KEY` / `KB_EMBED_API_KEY` 缺失 → **记 ERROR**，并把 `KB.enabled` 置假（`/kb/info` 返回 `enabled:false`，前端不渲染悬浮球，`/kb/chat` 返回 503）。宁可没有客服，也不要一个点了就报错的按钮。
3. `kb_settings.embed_dim` 与 `KB_EMBED_DIM` 不一致 → 记 ERROR，关闭向量检索（仅 FTS + 引导话术），后台 `/kb/admin/stats` 里显示"维度不一致，需重建索引"。

**预热索引**：启动后异步触发一次 `kb_index.ensure_loaded()`（用 `asyncio.create_task`），让首个用户请求不承担冷加载。

### 6.1 流式 Markdown 渲染（块级 keyed）

复用 `frontend/src/utils/markdown.js` 的管线（`marked` + `DOMPurify` + `hljs`），**零新依赖**。落地改动两处：

### 6.3 与后端通信（写进 `api/api.js`）

`api.js` 是前后端契约参照文件，**必须在这里声明 `/kb/chat`**。浏览器端 axios 无法读取 POST 响应的增量流，所以用 `fetch` 并显式注明原因：

```js
// 客服 API
// 注意：/kb/chat 是 SSE 流式接口，浏览器端 axios 不支持读取 POST 响应的增量 body，
// 因此这里用 fetch + ReadableStream 实现（baseURL 仍取自 McConfig，与其他接口保持一致）。
// 该接口是全项目唯一不返回 {code, message, data} 包络的接口，
// 帧协议见 docs/智能客服P0落地方案.md §4.3
export const chatAPI = {
  getInfo: () => axiosInstance.get('/kb/info'),

  streamChat: async ({ message, history = [], signal, onEvent }) => {
    const url = `${McConfig.baseApiURL}/kb/chat`;
    const res = await fetch(url, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ message, history }),
      signal,
    });
    if (!res.ok) {
      let msg = `请求失败：${res.status}`;
      try { const j = await res.json(); msg = j.detail || j.message || msg; } catch {}
      throw new Error(msg);
    }
    const reader = res.body.getReader();
    const decoder = new TextDecoder();
    let buf = '';
    for (;;) {
      const { done, value } = await reader.read();
      if (done) break;
      buf += decoder.decode(value, { stream: true });
      const frames = buf.split('\n\n');
      buf = frames.pop() || '';                    // 末段可能不完整，留到下一轮
      for (const frame of frames) {
        for (const line of frame.split('\n')) {
          if (!line.startsWith('data:')) continue;  // 忽略 ": ping" 保活注释
          const payload = line.slice(5).trim();
          if (!payload || payload === '[DONE]') continue;
          try { onEvent(JSON.parse(payload)); } catch { /* 单帧解析失败不中断整条流 */ }
        }
      }
    }
  },
};
```

同时在 `api/api.js` 末尾的默认导出里加上 `chat: chatAPI`。

> dev 环境不需要给主站加 Vite 代理：`McConfig.baseApiURL` 在 dev 是绝对地址 `http://localhost:5000`，且后端 `allow_origins=["*"]` 已开。**admin 前端不同**——它 `baseURL: ""` 走相对路径，必须加代理（见 §7.3）。

```nginx
location /kb/ {
    proxy_pass http://127.0.0.1:5000;
    proxy_http_version 1.1;
    proxy_set_header Connection '';
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;   # 限流按真实 IP，需后端读 X-Forwarded-For
    proxy_buffering off;                       # 必须，否则 SSE 被缓冲成一次性返回
    proxy_cache off;
    gzip off;                                  # 压缩缓冲会拖慢流式
    proxy_read_timeout 300s;
    chunked_transfer_encoding off;
}
```

> `X-Accel-Buffering: no` 响应头 + Nginx `proxy_buffering off` **两个都要**，只配一个在某些 Nginx 版本/配置下会失效。

**增量同步机制**：

```
对 KB_WIKI_DIR 下每个 *.md 计算 MD5
├─ kb_documents 中无 source_path 记录        → 新增（入库 + 切片 + Embedding）
├─ 有记录且 MD5 相同                          → 跳过（零成本）
├─ 有记录且 MD5 不同                          → 先删旧 chunks + FTS + 向量，再重建（幂等）
└─ 有记录但文件已不存在                      → 删除记录及切片（--prune 开关控制，默认开）
最后自增 kb_settings.index_version → 服务端下次对话自动重建内存索引，无需重启
```
