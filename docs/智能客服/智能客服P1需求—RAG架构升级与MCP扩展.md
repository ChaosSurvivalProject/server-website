

# 智能客服P1需求—RAG架构升级与MCP扩展

## 1. 产品架构定位
*   **核心架构**：默认启用 **Agentic RAG**，系统将“知识库检索”作为内置基础工具交予 LLM 自主决策调用。
*   **扩展能力**：通过 MCP Client 动态接入外部工具（如 MineMCP 插件）。MCP 仅作为能力的“扩展包”，独立启停，不改变主架构。

---

## 2. 后台管理侧（Admin Control Plane）
### 2.1 MCP Server 配置管理
*   **功能描述**：支持管理员注册和管理多个 MCP Server 连接信息。
*   **交互细节**：
    *   **配置方式**：
        *   *手动配置*：填写名称、URL、认证 Token（如 Bearer Token）。
        *   *JSON 导入*：支持粘贴标准 MCP 配置文件，自动解析填充。
    *   **协议支持**：`stdio`、`SSE`、`Streamable HTTP`。
    *   **连接测试**：配置后点击“测试连接”，状态栏显示“连接成功/失败”。
*   **单服务独立开关**：
    *   **功能**：在 MCP Server 列表中，每个 MCP Server 具备独立的“启用/停用”开关。
    *   **生效逻辑**：当某个 MCP Server 被停用时，系统**自动忽略该 Server 下的所有工具**，它们既不进入 LLM 上下文，也不会被路由执行。这用于在插件维护或发现安全风险时，单独下线某一个 MCP，而不影响系统整体（内置 RAG 依然正常工作）。

### 2.2 工具白名单管理（精细控制）
*   **功能描述**：即使某个 MCP Server 处于“启用”状态，管理员仍需在此对其暴露的工具进行二次勾选。
*   **交互细节**：
    *   **列表展示**：按 MCP Server 分组展示工具名称、描述。
    *   **启用/停用状态**：默认全部**关闭**。
    *   **生效逻辑**：只有既开启了 MCP Server，又在此处勾选了工具，该工具才会被转换为 LLM 的 Function Calling 定义。

### 2.3 内置知识库检索工具
*   **功能描述**：将原有的 RAG 检索能力封装为系统内置工具。
*   **配置项**：工具名称（默认 `search_knowledge_base`）、工具描述（供 LLM 理解何时调用）、Top-K 召回数量等。
*   **特性**：此工具为**系统级常驻工具**，不受 MCP 启停影响。

## 3. Agent 层（Orchestration Layer）
### 3.1 系统提示词动态组装
*   **组装逻辑**：
    *   `[角色设定]`：“你是一名 Minecraft 私服客服助手。”
    *   `[知识检索规范]`：“回答私服规则、玩法教程等静态问题时，必须优先调用 `search_knowledge_base`。”
    *   `[实时信息规范]`：“涉及服务器当前状态（如在线人数、日志），请调用对应的 MCP 工具。”
    *   `[异常处理规范]`：“如果工具调用失败，请安抚用户并提示稍后再试，禁止暴露底层报错。”

### 3.2 工具定义动态转换 (Schema Translation)
*   **处理逻辑**：Agent 层接收到的可用工具列表 = **（内置知识库工具） + （所有处于启用状态的 MCP Server 中、且被白名单勾选的工具）**。
*   **场景 A：未启用任何 MCP Server**。
    *   Agent 层仅向 LLM 提供 `search_knowledge_base` 这 1 个工具。LLM 依然走 Agentic RAG 流程（思考 -> 调工具 -> 看结果 -> 回答）。
*   **场景 B：启用了部分 MCP Server**。
    *   Agent 层将 RAG 工具与筛选后的 MCP 工具合并，一并转译给 LLM。
*   **断连处理**：若某个启用的 MCP Server 发生网络断连，Agent 层在组装上下文时自动剔除其相关工具，静默降级。

### 3.3 工具路由与执行
*   **路由逻辑**：接收 LLM 的 `tool_calls` 意图 → 判断是 `内置知识库` 还是 `MCP 工具` → 分别走本地向量库检索或 HTTP 请求 → 获取结果返回给 LLM。
*   **失败处理（优雅降级）**：
    *   **超时/网络异常**：向 LLM 注入 `{"error": "该查询功能暂时不可用，请引导用户联系人工"}`。
    *   **业务报错**：拦截 MCP 底层技术报错，隐藏堆栈信息。

## 4. 智能客服聊天页面（Frontend UI）
### 4.1 对话流与工具调用链路展示
*   **功能描述**：以折叠面板或进度条形式，向用户展示 Agent 的思考与动作过程。
*   **展示规则**：
    *   **语义化动作名**：显示 `📖 正在检索知识库...` 或 `🔍 正在查询服务器状态...`。
    *   **严格隐藏参数**：前端接口绝对不下发实际调用的 JSON 参数或底层命令，防止敏感信息泄露。
*   **交互状态**：
    *   **调用中**：转圈 Loading + 动作名。
    *   **成功**：`✅ 检索完成` / `✅ 获取成功`。
    *   **失败**：`❌ 查询超时，已转入备用回复`。

---

## 5. 非功能性需求（NFR）
*   **安全审计**：后台需记录所有工具（含 RAG 检索）的调用日志，包含用户 Prompt、LLM 决策、实际执行参数、执行结果，用于排查幻觉与越权攻击。
*   **性能控制**：
    *   知识库检索应控制在 1 秒内返回。
    *   MCP 工具调用（HTTP 请求）设定 3-5 秒超时限制，防止由于游戏服卡顿导致 AI 整体响应迟迟不返回。
