# 资源中心板块实现需求（MVP）——一阶段

## 0. 项目背景与核心约束

官网 `https://xqly.xt91tv.shop` 当前有“首页”“社区”两个板块，现新增“资源中心”板块，用于展示组织下自研的模组、插件等资源。

管理后台已存在，本次在后台扩展资源管理能力。当前阶段：

- **资源与版本信息由后台手动维护**；
- **不做 GitHub 自动同步**；
- **下载直接跳转 GitHub Release 资产链接**；
- **不做文件代理、缓存、SHA-256 校验**；
- 网站侧只记录**下载按钮跳转点击次数**，口径必须命名为“下载跳转次数”，不得称为“下载量”；
- 前台必须提示“下载文件由 GitHub 托管”。

---

## 1. 目标与范围

### 1.1 P0 必须实现

1. 后台资源元数据管理；
2. 后台版本管理、版本下资产链接管理；
3. 前台资源列表页，支持搜索、筛选、排序、分页/加载更多；
4. 前台资源详情页，展示资源信息、版本列表、下载入口；
5. 下载跳转端点 `/download/asset/{assetId}`，记录跳转事件后 302 到后台录入的 GitHub Release 资产 URL；
6. 后台查看下载跳转统计；
7. 导航新增“资源中心”入口；
8. 移动端可用；
9. 软删除、发布/隐藏/下架状态控制；
10. 基本防刷和开放重定向防护。

### 1.2 P1 可选增强

- 后台表单支持粘贴 GitHub Release URL 后辅助解析 tag、仓库、附件文件名，但仍需人工确认保存。这不是自动同步。
- 同一 IP 对同一资产 24 小时内只计一次展示计数，但事件仍记录。
- 首页展示“最新/精选资源”卡片。
- 列表/网格视图切换。

### 1.3 明确不做

- 不做 GitHub 自动同步、Webhook、定时任务；
- 不做文件上传、文件代理、下载缓存；
- 不做 SHA-256 校验；
- 不做 GitHub API 下载量同步；
- 不做用户评论、评分、收藏；
- 不做用户投稿、付费下载、权限下载；
- 不做高级全文搜索，MVP 用 `LIKE` 即可；
- 不重构首页、社区、全局导航。

## 2. 核心口径：下载跳转计数

前台下载按钮不得直接暴露 GitHub 链接，必须指向本站：

`GET /download/asset/{assetId}`

处理逻辑：

1. 根据 `assetId` 查询资产、版本、资源；
2. 校验资产可见、版本可见、资源状态为已发布；
3. 校验资产 URL 为后台录入的 `https://github.com/...` Release 资产链接；
4. 记录一条 `download_event`；
5. 返回 `302` 到该资产的 GitHub URL。

安全要求：

- 端点**不接受任意 URL 参数**，只根据数据库中的 `assetId` 查 URL，防止开放重定向；
- 资产不存在、已隐藏、版本已隐藏/下架、资源非已发布状态时，不跳转，返回 404 或 410；
- 最低防刷：按 `IP + assetId` 做速率限制；
- 不存原始 IP，存 IP 哈希或截断值；
- 前台和后台展示文案统一为“下载跳转次数”，tooltip 或说明注明：“本站记录的是下载按钮跳转点击次数，文件由 GitHub 托管，非 GitHub 实际下载量。”

## 3. 数据模型建议

### 3.1 字典表

建议可配置字典，避免平台、游戏版本、资源类型写死：

`dict_items`

- `id`
- `type`：resource_type / platform / game_version / side / release_channel / tag
- `key`
- `label`
- `sort`
- `enabled`
- `timestamps`

### 3.2 资源表 `resources`

- `id`
- `slug`：唯一，用于前台 URL
- `name`
- `resource_type_id` 或 `resource_type_key`
- `summary`：一句话简介
- `description_md`：Markdown 详情
- `icon_url`
- `cover_url`
- `side`：client / server / both
- `status`：draft / published / hidden / archived
- `featured`：是否推荐
- `sort_weight`
- `github_repo_url`
- `issues_url`
- `docs_url`
- `created_by`
- `created_at` / `updated_at`
- `deleted_at`：软删除

多对多关联：

- `resource_platforms`
- `resource_game_versions`
- `resource_tags`

资源级平台、游戏版本、侧别、标签用于**列表筛选**。后台需提示：资源级兼容范围应覆盖其所有可见版本。

### 3.3 版本表 `resource_versions`

- `id`
- `resource_id`
- `version`：如 `1.2.0`，同一资源下唯一
- `release_tag`：GitHub tag
- `channel`：stable / beta / alpha
- `published_at`
- `game_versions`：JSON 多值，用于详情展示
- `platforms`：JSON 多值，用于详情展示
- `side`：client / server / both
- `changelog_md`
- `status`：visible / hidden / archived
- `is_latest_stable`：每个资源最多一个
- `created_at` / `updated_at`
- `deleted_at`

### 3.4 下载资产表 `version_assets`

一个版本可挂多个文件：

- `id`
- `version_id`
- `filename`
- `url`：必须为 `https://github.com/` 开头的 Release 资产链接
- `purpose`：main / additional
- `sort`
- `is_primary`
- `status`：visible / hidden
- `created_at` / `updated_at`
- `deleted_at`

### 3.5 下载事件表 `download_events`

- `id`
- `resource_id`
- `version_id`
- `asset_id`
- `created_at`
- `ip_hash`
- `user_agent`：可选
- `referer`：可选

统计维度：资源总跳转次数、按版本、按资产、按时间范围。

## 4. 后台功能需求

复用现有后台登录与权限，新增资源管理模块。

### 4.1 资源管理

- 资源列表：搜索、按状态筛选、排序；
- 新建/编辑资源：字段见 3.2；
- 发布、隐藏、归档、软删除；
- 设置推荐与排序权重；
- 资源 slug 唯一性校验；
- 资源级平台/游戏版本/标签多选。

### 4.2 版本管理

- 在资源下管理版本列表；
- 新建/编辑版本：版本号、release tag、渠道、发布日期、兼容游戏版本、平台、侧别、更新日志、状态；
- 同一资源下版本号唯一；
- 设置“最新稳定版”，每个资源最多一个；
- 版本隐藏/下架后，其资产不可下载。

### 4.3 资产管理

- 在版本下管理资产；
- 字段：文件名、GitHub Release 资产 URL、用途、排序、是否主资产、状态；
- URL 必须为 `https://github.com/`；
- 主下载资产最多一个，若无主资产则取排序第一个可见资产；
- 资产隐藏后不可下载。

### 4.4 统计与审计

- 查看资源/版本/资产的下载跳转次数；
- 支持时间范围筛选；
- 记录后台操作审计：谁在何时修改了什么；
- 软删除数据不物理删除，便于追溯。

## 5. 前台布局与交互

参考 Modrinth Browse / Project 页布局，但保持官网现有视觉风格。

### 5.1 导航

官网顶部导航新增“资源中心”，进入 `/resources`。不重构全局导航。

### 5.2 资源列表页 `/resources`

整体结构：

```
[官网顶部导航]
[资源中心页头：标题 + 搜索框 + 排序]
[左侧筛选栏]  [主内容区：资源卡片网格 + 加载更多]
```

页头：

- 搜索框：按名称、简介关键词搜索；
- 排序：最近更新、名称、下载跳转次数；
- MVP 只做网格视图。

左侧筛选栏：

- 资源类型：单选或“全部”；
- 平台/加载器：多选；
- 游戏版本：多选，可折叠/搜索；
- 侧别：客户端/服务端/双端；
- 发布渠道：Stable/Beta/Alpha；
- 标签：多选。

要求：

- 筛选条件写入 URL query，如 `?platform=fabric&game_version=1.21&sort=updated_desc`，可分享、可回退；
- 桌面端左侧常驻；移动端收敛为“筛选”按钮，抽屉/全屏展开；
- 主区使用响应式网格：桌面 3—4 列，平板 2 列，移动 1 列；
- 分页使用“加载更多”按钮。

资源卡片：

```
[封面/横幅，统一比例；无图用占位]
[图标] 资源名称              [类型徽章]
       一句话简介，最多 2 行
[平台标签] [版本标签] [侧别]
下载跳转 1.2k · 最近更新 3 天前
```

要求：

- 整个卡片可点击进入详情页；
- 卡片只展示 2—3 个关键标签，完整标签在详情页；
- 卡片不展示完整版本列表；
- 下载跳转次数文案为“下载跳转”；
- 封面统一比例，无封面用占位图，避免卡片高度不一致；
- 不做全宽大横幅轮播。

### 5.3 资源详情页 `/resources/{slug}`

双栏布局：

```
[返回资源中心]
[图标] 资源名称 [类型] [状态]
       一句话简介
────────────────────────────────
[主内容区]                     [右侧栏]
- Markdown 详细描述            - 下载面板
- 标签与特性                   - 最新稳定版下载按钮
- 版本列表 / 更新日志          - 平台/版本/侧别
- GitHub 仓库/Issues 链接      - 兼容性一览
                               - 下载跳转次数
```

要求：

- 右侧栏下载按钮指向 `/download/asset/{assetId}`；
- 展示“下载文件由 GitHub 托管”提示；
- 版本列表每行：版本号 + 渠道徽章 + 兼容游戏版本/平台 + 发布日期 + 下载按钮；
- 旧版本允许下载，除非后台隐藏/下架；
- 移动端侧栏下沉，下载按钮可做吸底栏；
- 无可见版本时显示空状态，不显示下载按钮。

## 6. API 建议

### 6.1 前台只读 API

`GET /api/resources`

参数：

- `q`
- `type`
- `platform`：可多值
- `game_version`：可多值
- `side`
- `channel`
- `tag`：可多值
- `sort`：updated_desc / name_asc / downloads_desc
- `page`
- `page_size`

返回：`items`、`total`、`page`、`page_size`。列表筛选基于资源级字段，多对多查询需避免重复计数。

`GET /api/resources/{slug}`

返回资源详情、最新稳定版、版本列表、每个版本的可见资产、下载跳转统计。

`GET /api/filters`

返回可用筛选项字典。

### 6.2 下载端点

`GET /download/asset/{assetId}`

逻辑见第 2 节。成功 302；不可用返回 404/410；速率限制可返回 429。

### 6.3 后台 API

资源、版本、资产 CRUD；发布状态切换；统计查询；审计查询。复用现有后台鉴权。

## 7. 验收标准

满足以下条件视为 MVP 完成：

1. 后台可创建资源，维护类型、简介、描述、平台、游戏版本、侧别、标签、GitHub 链接、状态、推荐与排序；
2. 后台可在资源下创建多个版本和多个下载资产，版本号唯一，最多一个最新稳定版；
3. 前台列表可按资源类型、平台、游戏版本、侧别、发布渠道、标签筛选，可关键词搜索、排序，筛选条件在 URL 中可分享；
4. 前台详情页展示资源信息、兼容信息、版本列表和下载按钮；
5. 下载按钮走 `/download/asset/{assetId}`，302 到后台录入的 GitHub URL；
6. 下载端点不接受任意 URL 参数，隐藏/下架/草稿资源不可跳转；
7. 每次有效跳转记录事件，后台可按资源/版本/资产查看“下载跳转次数”；
8. 前台明确提示文件由 GitHub 托管，计数口径文案正确；
9. 移动端列表筛选可用，详情页下载入口可触达；
10. 软删除生效，删除后前台不可见，后台可追溯；
11. 无 N+1 查询导致列表明显变慢，多对多筛选不产生重复资源项。

## 8. 建议开发顺序

1. 数据库迁移：字典表、资源、版本、资产、事件表；
2. 后台资源/版本/资产 CRUD 与状态控制；
3. 下载端点、事件记录、防开放重定向与限速；
4. 前台只读 API：列表、详情、筛选项；
5. 前台列表页：搜索、筛选、排序、URL query、响应式网格；
6. 前台详情页：双栏布局、版本列表、下载面板；
7. 后台统计与审计；
8. 移动端适配与验收测试。
